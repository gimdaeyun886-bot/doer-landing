# Do-er

**배포 URL:** https://doer-landing-nine.vercel.app

## 서비스 소개

Do-er는 "계획은 세우는데 실행이 안 되는" 사람을 위한 AI 실행 코치입니다.
첫 대상은 퇴근 후 자격증 시험을 준비하는 직장인입니다.

1. **계획** — 목표와 시험일을 말하면 AI가 전체 계획을 짜고 오늘 할 일로 나눕니다.
2. **잠금** — 시작하면 내가 고른 방해 화면(릴스·쇼츠·스토리 등)이 잠깁니다.
3. **인증** — 끝낸 일을 인증하면 잠금이 풀립니다.
4. **조정** — 버거운 날에는 코치에게 사유를 말하고, 조정안을 수락하거나 유지합니다.

이 저장소에는 두 가지가 들어 있습니다.

- `/` — 서비스를 소개하는 랜딩 페이지 (미션 5)
- `/tasks` — 오늘 할 일을 등록하고 끝낸 증거 이미지로 인증하는 실행 기록 (미션 6, 이 문서의 주 내용)

> 로그인 없이 누구나 읽고 쓸 수 있는 연습용 기록입니다. 개인정보나 민감한 자료는 저장하지 않습니다. 사용자별 접근 제어는 다음 미션에서 적용합니다.

## 핵심 기능 명세: 할 일과 인증 자료

Do-er의 핵심 가치는 "오늘 할 일을 끝내고 증거로 인증한다"입니다. 그래서 CRUD 대상을 **할 일(task)** 로 정하고, 파일 업로드를 **인증 자료 이미지**로 연결했습니다. 인증 자료가 있으면 "인증 완료", 없으면 "인증 전"으로 표시합니다.

### 사용자 흐름

목록(`/tasks`) → 상세(`/tasks/[id]`) → 등록(`/tasks/new`) 또는 수정(`/tasks/[id]/edit`) → 상세로 돌아옴. 삭제는 상세 화면에서 확인 창을 거친 뒤 목록으로 돌아갑니다.

### 화면별 명세

| 화면 | 입력 | 사용자 행동 | 성공 결과 | 실패 결과 |
|---|---|---|---|---|
| 목록 `/tasks` | 검색어, 인증 상태, 페이지 번호 (주소의 `q`, `status`, `page`) | 카드 눌러 상세로 이동, 검색·필터, 페이지 이동, 등록 버튼 | 날짜가 최근인 순서로 6개씩 표시 | 조회 실패 시 오류 화면과 "다시 시도", 데이터가 없으면 빈 상태 안내, 범위를 넘은 페이지는 마지막 페이지로 이동 |
| 상세 `/tasks/[id]` | 없음 | 수정으로 이동, 삭제, 인증 자료 크게 보기 | 내용과 인증 이미지 표시. 이미지가 없으면 "아직 인증 전" 안내 | 없는 주소나 삭제된 항목은 "할 일을 찾을 수 없어요" 화면 |
| 등록 `/tasks/new` | 할 일, 목표, 날짜, 예상 시간(분), 메모(선택), 인증 이미지(선택) | 입력 후 "등록하기" | 저장 후 상세로 이동, "할 일을 등록했어요" 표시 | 항목별 오류 메시지 표시, 입력값 유지. 업로드나 저장 실패 시 안내 문구 |
| 수정 `/tasks/[id]/edit` | 등록과 같음 + 기존 이미지 삭제 선택 | 기존 값을 고친 뒤 "저장하기" | 저장 후 상세로 이동, "수정한 내용을 저장했어요" 표시 | 등록과 같음. 이미 삭제된 항목이면 안내 문구 |
| 삭제 (상세의 확인 창) | 없음 | "삭제" → 확인 창에서 "삭제하기" 또는 "취소" | 레코드와 인증 이미지 삭제 후 목록으로 이동, "할 일을 삭제했어요" 표시 | 확인 창 안에 오류 문구 표시 |

### 입력 규칙

| 항목 | 필수 | 규칙 |
|---|---|---|
| 할 일 | 필수 | 1~60자 |
| 목표 | 필수 | 1~30자 |
| 날짜 | 필수 | 실제로 있는 날짜 (YYYY-MM-DD) |
| 예상 시간 | 필수 | 5~600 사이의 정수(분) |
| 메모 | 선택 | 300자 이하 |
| 인증 이미지 | 선택 | JPG, PNG, WEBP · 3MB 이하 |

같은 규칙을 서버에서 검사하고, 데이터베이스 제약 조건으로 한 번 더 막습니다. 이미지 형식과 크기는 브라우저에서 먼저 걸러 내고 서버에서 다시 확인합니다. 저장하는 동안에는 입력칸과 버튼이 잠겨 중복 제출을 막고, 버튼 글자가 "등록 중…"으로 바뀝니다.

## 테이블 구조

Supabase(PostgreSQL)의 `public.tasks` 테이블 하나를 씁니다. 전체 SQL은 [supabase/schema.sql](supabase/schema.sql)에 있습니다.

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | uuid | 필수 (기본값 자동 생성) | 고유 식별자, 기본 키 |
| `title` | text | 필수 | 할 일 (1~60자) |
| `goal` | text | 필수 | 목표 또는 시험 이름 (1~30자) |
| `due_date` | date | 필수 | 할 날짜 |
| `estimated_minutes` | integer | 필수 | 예상 시간(분), 5~600 |
| `memo` | text | 선택 | 메모 (300자 이하) |
| `proof_path` | text | 선택 | 인증 이미지의 Storage 경로. 비어 있으면 인증 전 |
| `created_at` | timestamptz | 필수 (기본값 현재 시각) | 생성 시각 |
| `updated_at` | timestamptz | 필수 (트리거로 자동 갱신) | 수정 시각 |

인증 이미지는 Supabase Storage의 공개 버킷 `task-proofs`에 저장하고, 파일 경로를 `proof_path`에 적어 레코드와 연결합니다. 이미지를 바꾸거나 할 일을 삭제하면 이전 파일도 함께 지웁니다.

이번 미션에서는 인증과 권한을 구현하지 않으므로 RLS를 끈 상태로 공개 키에 읽기·쓰기를 허용했습니다.

## 기술 스택

- Next.js 16 (App Router, Server Actions), React 19, TypeScript
- Supabase (PostgreSQL, Storage)
- 배포: Vercel
- 랜딩 페이지: HTML, CSS, JavaScript 정적 파일 (`public/`)

## 실행 방법

1. 패키지를 설치합니다.

   ```bash
   npm install
   ```

2. Supabase 프로젝트를 만들고, SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다.
3. `.env.example`을 `.env.local`로 복사한 뒤 값을 채웁니다.
4. 개발 서버를 실행하고 `http://localhost:3000/tasks`를 엽니다.

   ```bash
   npm run dev
   ```

## 환경 변수

| 이름 | 설명 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 주소 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase 공개 키 (publishable, 예전 이름 anon) |

로컬은 `.env.local`에, 배포는 Vercel의 Project Settings → Environment Variables에 같은 이름으로 넣습니다. 실제 값은 저장소에 올리지 않습니다.

