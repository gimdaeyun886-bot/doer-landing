# QA 체크리스트

결과는 통과, 실패, 미점검으로 적습니다.

- **배포:** `node scripts/e2e.mjs https://doer-mission6.vercel.app`로 실제 브라우저(Edge, 390px 폭)를 띄워 화면을 직접 눌러 점검했습니다. AI와 데이터베이스는 실제 서비스를 씁니다. 최종 코드(커밋 `7e6a217`)로 2026-10-16에 42개 항목을 모두 통과했습니다.
- **로컬:** 같은 스크립트를 개발 서버에 돌렸습니다. 검색·필터 항목을 더하기 전 코드로 39개 항목을 모두 통과했고, 더한 뒤에는 검색·필터 항목까지 통과한 다음 컴퓨터의 네트워크가 끊겨 중간에 멈췄습니다. 끊긴 원인은 앱이 아니라 점검하던 컴퓨터의 연결이었고, 같은 코드로 배포 환경에서는 끝까지 통과했습니다.
- 두 번 모두 빈 데모 공간에서 시작했고, 점검이 끝난 뒤 점검용 목표를 지웠습니다.

## 과제 필수 시나리오

| 번호 | 시나리오 | 기대 결과 | 로컬 | 배포 |
|---|---|---|---|---|
| A1 | 빈 값으로 제출 | 확인 장에서 목표를 비우고 "계획 만들기"를 누르면 저장되지 않고 "무엇을 해내고 싶은지 적어 주세요"가 뜸 | 통과 | 통과 |
| A2 | 잘못된 형식의 파일 | PDF와 3MB가 넘는 PNG는 고르는 순간 막고 "JPG, PNG, WEBP 이미지만", "3MB 이하만" 안내 | 통과 | 통과 |
| A3 | 등록 후 목록·상세 반영 | 저장하면 계획을 짜고 상세로 이동. 목록에 목표가 보임 | 통과 | 통과 |
| A4 | 새로고침 후 데이터 유지 | 상세와 목록을 새로고침해도 같은 내용 | 통과 | 통과 |
| A5 | 수정 후 화면 반영 | 바꾼 제목이 상세와 목록에 보이고, 계획을 다시 짬 | 통과 | 통과 |
| A6 | 삭제 후 화면 반영 | 확인 창을 거쳐 지우면 목록에서 사라짐 | 통과 | 통과 |
| A7 | 존재하지 않는 상세 주소 | 지운 목표의 주소와 `/goals/abc` 모두 "목표를 찾을 수 없어요" | 통과 | 통과 |
| A8 | 파일이 없는 경우 | 자료 사진 없이 등록한 목표의 상세에 "올린 자료가 없어요" 안내 | 통과 | 통과 |
| A9 | 파일을 올린 경우 | 수정에서 올린 사진이 Storage(`mission-materials/materials/…`)에 저장되고 상세에 보임 | 통과 | 통과 |

A10은 저장소 오류를 일부러 일으킬 방법이 없어 점검하지 못했습니다. 코드에서는 업로드가 실패하면 저장을 멈추고 입력값과 안내 문구를 돌려줍니다(`app/goals/actions.ts`의 `UPLOAD_FAILED`). 형식이나 크기가 틀린 파일은 A2처럼 올리기 전에 막고, 서버와 버킷 설정에서도 한 번 더 막습니다.
