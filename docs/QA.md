# QA 체크리스트

결과는 통과, 실패, 미점검으로 적습니다.

- **로컬:** `node scripts/e2e.mjs`로 실제 브라우저(Edge, 390px 폭)를 띄워 화면을 직접 눌러 점검했습니다. 데이터는 실제 Supabase에 저장됩니다. 2026-10-15에 45개 항목을 모두 통과했습니다.
- **배포:** 같은 스크립트에 배포 주소(https://doer-mission6.vercel.app)를 넣어 같은 방식으로 점검했습니다. 2026-10-15에 45개 항목을 모두 통과했습니다.

## 과제 필수 시나리오

| 번호 | 시나리오 | 기대 결과 | 로컬 | 배포 |
|---|---|---|---|---|
| A1 | 빈 값으로 제출 | 목표를 비우거나, 날짜 없이 "정한 날까지"를 고르거나, 요일을 하나도 고르지 않으면 다음 단계로 넘어가지 않고 칸 아래에 오류 문구가 뜸 | 통과 | 통과 |
| A2 | 잘못된 값으로 제출 | 하루 5분처럼 범위를 벗어난 값은 막음. 브라우저의 글자 수 제한을 지우고 41자를 보내도 서버가 막고, 그 칸이 있는 단계로 돌려보냄. 다른 답은 그대로 남음 | 통과 | 통과 |
| A3 | 잘못된 형식의 파일 | PDF와 3MB가 넘는 PNG는 고르는 순간 막고 "JPG, PNG, WEBP 이미지만", "3MB 이하만" 안내 | 통과 | 통과 |
| A4 | 등록 후 목록·상세 반영 | 상세로 이동해 D-30, 기간 막대, 달력, 잠글 앱, 지금 상황이 보이고 목록에도 카드가 생김 | 통과 | 통과 |
| A5 | 새로고침 후 데이터 유지 | 상세와 목록을 새로고침해도 내용이 같음 | 통과 | 통과 |
| A6 | 수정 후 화면 반영 | 바꾼 제목, 종류(매주 반복), 요일(주말), 하루 시간이 상세에 반영되고 목록에도 바뀐 제목이 보임 | 통과 | 통과 |
| A7 | 삭제 후 화면 반영 | 확인 창에서 "그대로 두기"를 누르면 남아 있고, "지우기"를 누르면 목록에서 사라짐 | 통과 | 통과 |
| A8 | 존재하지 않는 상세 주소 | `/goals/abc`, 없는 id, 없는 id의 수정 주소, 지운 목표의 주소 모두 "목표를 찾을 수 없어요". 없는 페이지는 "페이지를 찾을 수 없어요" | 통과 | 통과 |
| A9 | 파일이 없는 경우 | 사진 없이 등록한 목표의 상세에 "올린 사진이 없어요" 안내 | 통과 | 통과 |
| A10 | 파일을 올린 경우 | 수정에서 고른 사진의 미리보기가 보이고, 저장하면 Storage(`mission-materials/goals/…`)에 올라가 상세에 표시됨 | 통과 | 통과 |
| A11 | 파일을 지운 경우 | 수정에서 사진을 지우면 상세에서 빠지고 Storage의 파일도 지워짐(파일 주소가 400 응답) | 통과 | 통과 |
| A12 | 업로드에 실패한 경우 | 저장소 오류가 나면 "사진을 올리지 못했어요" 안내가 뜨고 입력값은 유지됨 | 미점검 | 미점검 |

A12는 저장소 오류를 일부러 일으킬 방법이 없어 점검하지 못했습니다. 코드에서는 업로드가 실패하면 저장을 멈추고 입력값과 안내 문구를 돌려줍니다(`app/goals/actions.ts`의 `UPLOAD_FAILED`). 형식이나 크기가 틀린 파일은 A3처럼 올리기 전에 막고 서버와 버킷 설정에서도 한 번 더 막습니다.
